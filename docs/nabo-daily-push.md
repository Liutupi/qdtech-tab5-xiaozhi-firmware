# NABO 每日推送：页面设计与推送约定（给 Grok）

> 设备：M5Stack Tab5（1280×720 横屏，触摸）。固件仓库：`Liutupi/qdtech-tab5-xiaozhi-firmware`。
> 中转站：NAS 上现有的 muse-relay（`tools/muse-relay/`）。
> 本文说明「每日推送」页和主页提醒怎么设计，以及推送内容的格式。效果图在 claude.ai 的私有画布上，你打不开，以本文为准。

## 1. 总体思路

- **单向推送**：内容只从服务端推到 Tab5，Tab5 上不能提问。界面上所有来源统一显示为 **Nabo**（不显示 Muse、Grok）。
- **主页负责提醒，推送页负责阅读**。主页已经有时间、天气和 NABO 动画，推送页不再重复。
- 推送页左侧固定 **四个板块**：今日运势、今日学习、今日待办、往日回顾。不再增加板块。
- 前三个板块由服务端推送；**往日回顾由 Tab5 用本地历史自动生成，服务端不推**。
- 「已读」「学会了」「收藏」「待办完成」这些状态都只存在 Tab5 本地，不回写服务端。

## 2. 推送页（每日推送）

```
┌ 每日推送   10月22日 周四 · Nabo                  (3) [全部已读] [返回] ┐
│ ┌──────────┐ ┌────────────────────────────────────────────────┐ │
│ │ 今日运势 • │ │                                                │ │
│ │ 今日学习 • │ │            当前板块的内容区（约 992×600）          │ │
│ │ 今日待办   │ │                                                │ │
│ │ 往日回顾   │ │                                                │ │
│ └──────────┘ └────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```

- 风格：深色底 `#0E1117`，卡片 `#171C25`，主色暖橙 `#F5A04A`。
- 字号按一臂距离可读：页面和卡片标题 28px，正文 20–22px，诗句、卦名等 30px 以上；触控目标不小于 48px。
- 左侧板块按钮：名称加一行概况（如“★★★★☆ 稳中有进”“2 / 6 已完成”）。有新内容的板块右上角亮一个橙点。
- 未读总数只在右上角的橙色圆标显示一处。
- 模块页和详情卡的文字超长时，在卡片内部滚动，不撑破布局。

### 2.1 今日运势（两层）

顶部一排 9 个标签，默认停在「综合」：

`综合 · 称骨 · 周易 · 灵签 · 塔罗 · 黄历 · 星座 · 紫微 · 奇门`

**综合页**

- 左边大卡：日期与“来自 Nabo”、星级（1–5）、一句话总评、宜、忌，底部是 Nabo 的一句提醒。
- 右边：幸运色、幸运数字；五项分数条：事业科研 / 健康 / 家庭 / 财运 / 心情（各 1–5）。

**模块页**（每个模块一张卡）

| 模块 | 卡片内容 |
|---|---|
| 称骨 | 骨重大字（如“四两三钱”）、歌诀前两句、白话一句 |
| 周易 | 本卦、变卦（卦名 + 六爻图，动爻标橙）、卦辞白话 |
| 灵签 | 签号、吉凶等级、四句签诗、解签一句 |
| 塔罗 | 三张牌：过去 / 现在 / 未来，各写牌名、正位或逆位、一句解读 |
| 黄历 | 农历日期、年月日干支、值神、建除、宜、忌 |
| 星座 | 星座名、四项今日指数（综合、爱情、事业、财运）、一句话 |
| 紫微 | 命宫主星、流日宫位、一句简评 |
| 奇门 | 吉方位、凶方位、一句建议 |

推送里缺了哪个模块，或模块为空，这个模块页就显示「暂无」。

### 2.2 今日学习

左边是列表，右边是详情：每条推送对应列表里的一张卡。

- 类型标签按 `source` 区分：`nabo/study/paper` 文献（紫）、`nabo/study/word` 单词（蓝）、`nabo/study/point` 知识点（绿）。
- 详情页：类型标签、来源与时间、标题、正文（保留换行），以及「学会了」「收藏」两个按钮。

### 2.3 今日待办

一张勾选清单：每个事项一条推送，顶部显示“已完成 x / y”和进度条。

- 如果 `title` 以 `HH:MM ` 开头（注意时间后面有一个空格），这段会被取出来当作时间，显示在左边。
- 按时间先后排序，没写时间的排在最后。勾选完成的项划掉、变灰，沉到底部。
- 完成状态存在 Tab5 本地，并计入往日回顾。

### 2.4 往日回顾（Tab5 本地生成）

- Tab5 每天把当天收到的推送，连同完成、学会、收藏状态存到本地，按天汇总，至少保留 30 天。
- 左边按日期倒序列出，每天一行概况，例如“★★★ · 2/3 学 · 4/5 办”。七天前那天标成“一周前的今天”。
- 右边是选中那天的汇总：当天运势一句、学习条目和学会数、待办完成数和没完成的项。
- 每一天都可以收藏，左上角可以切到“只看收藏”。

## 3. 主页提醒逻辑

同一时刻只提醒一条，按下表从上往下取第一条满足条件的。提醒时会做三件事：

- 主页的 NABO 插播一次对应动作（用 SD 卡 `lively-v1` 里已有的动作）；
- 主页每日卡片（438×94）换成对应内容；
- 点卡片直接进推送页的对应板块。

| 顺序 | 什么时候 | 板块 | NABO 动作 | 卡片显示 | 什么时候消失 |
|---|---|---|---|---|---|
| 1 | 带时间的待办，开始前 15 分钟 | 待办 | A07 指向右侧；`priority=high` 时加一声提示音 | “15′ 后开始 · 09:30 提交病例讨论 PPT” | 打勾完成；过点 1 小时后变灰 |
| 2 | 收到 `priority=high` 的推送 | 任意 | 用推送里的 `mood` | 这条推送的标题 | 点开看过 |
| 3 | 早上第一次亮屏（6:00–11:00） | 运势 | E06 闭眼满足笑 | 星级 + 总评 + 宜/忌 | 点开，或到 12:00 |
| 4 | 20:00 还有没点「学会了」的 | 学习 | P02 翻开小书 | “2 条没学 · 标题” | 全部学会，或到 23:00 |
| 5 | 周日 21:00 | 回顾 | A05 托腮思考 | 一周回顾 | 点开，或到周一早上 |
| – | 其他时间 | – | 原来的空闲轮播 | 每日一句，加一行小字概况 | – |

不打扰规则：

- 对话中、播放音乐或电台、睡眠、23:00–7:00：不插播动画，只换卡片。
- 同一条最多插播一次；两次插播之间至少隔 10 分钟。

`mood` 与 NABO 动作对照：idle → P02 翻开小书，alert → A07 指向右侧，rain → E10 摇头轻叹，happy → E06 闭眼满足笑，thinking → A05 托腮思考。

## 4. 推送格式

### 4.1 接口（沿用中转站现有的 token 机制）

token 放在路径里，写法和现有的 `/push/<token>`、`/home/<token>/…` 一样。**token 只从环境变量或 `/data/token.txt` 读取，不要写进代码、日志或聊天。**

| 方法 | 路径 | 谁用 | 作用 |
|---|---|---|---|
| POST | `/nabo/<token>/push` | 服务端（Nabo） | 推送一条；用同一个 `id` 再推会覆盖原内容 |
| GET | `/nabo/<token>/inbox?since=<rev>` | Tab5 | 每 60 秒拉取 `since` 之后新增或修改的推送 |

Tab5 上的状态都存在本地，不回写，所以没有状态接口。

- `push` 成功返回 `{"ok":true,"id":"…","rev":12,"deleted":false,"changed":true}`；出错返回 HTTP 400/413 和 `{"ok":false,"error":"bad_source"}` 这类错误码，错误码直接指出是哪个字段不对。
- 每次推送（包括覆盖和撤回）中转站都会把全局 `rev` 加 1。`since` 推荐传上次拿到的 `rev`（整数）；也可以传 ISO 时间，按中转站收到的时间过滤。只按推送里的 `ts` 拉会漏掉“同一个 `id` 改了内容但 `ts` 没变”的更新，所以 Tab5 用 `rev`。
- `inbox` 返回 `{"ok":true,"rev":<本页最后一条的 rev>,"latest_rev":…,"more":false,"items":[…]}`，按 `rev` 从小到大排；每页最多 100 条（`limit` 最大 200），`more=true` 时用返回的 `rev` 接着拉。
- 撤回的条目以 `{"id":"…","deleted":true,"rev":…}` 出现在 `items` 里，Tab5 收到后删除本地这条。
- 待办如果标题以 `HH:MM ` 开头，返回里会多一个规整好的 `time` 字段（如 `"09:30"`）。

### 4.2 公共字段

```json
{
  "id": "nabo-2026-10-22-todo-ppt",
  "ts": "2026-10-22T07:45:00+08:00",
  "source": "nabo/fortune | nabo/study/paper | nabo/study/word | nabo/study/point | nabo/todo",
  "priority": "high | normal | low",
  "mood": "idle | alert | rain | happy | thinking",
  "title": "不超过 40 字",
  "body": "不超过 600 字；运势这里放 JSON 字符串"
}
```

- `id`：由推送方生成，全局唯一。用同一个 `id` 再推会覆盖原内容；推 `{"id": "...", "deleted": true}` 表示撤回这一条。
- `ts`：带时区的 ISO 8601。Tab5 按它排序，并决定这条归到哪一天。
- `mood` 不填时按板块取缺省值：运势 `happy`，学习 `thinking`，待办 `alert`。
- **不要再推 `nabo/review`**，往日回顾由 Tab5 自己生成。

### 4.3 今日运势：`source = "nabo/fortune"`，`body` 是 JSON 字符串

每天推一条，后推的会覆盖先推的。`body` 解析出来的结构如下：

```json
{
  "score": 4,
  "summary": "稳中有进，适合把拖着的小事一口气做完。",
  "yi": ["整理文献", "早点睡", "约朋友吃饭"],
  "ji": ["熬夜", "冲动下单"],
  "color": "雾蓝",
  "number": 7,
  "bars": { "事业科研": 4, "健康": 3, "家庭": 4, "财运": 3, "心情": 4 },
  "nabo": "下午有雨，记得带伞的人运气不会差。",
  "modules": {
    "chenggu":  { "weight": "四两三钱", "verse": ["第一句", "第二句"], "plain": "白话一句" },
    "zhouyi":   { "gua": "地天泰", "gua_lines": [1,1,1,0,0,0], "bian": "地泽临", "bian_lines": [1,1,0,0,0,0], "moving": [3], "plain": "卦辞白话" },
    "lingqian": { "no": "第二十三签", "level": "中吉", "poem": ["句一", "句二", "句三", "句四"], "explain": "解签一句" },

                  { "pos": "现在", "name": "星星", "upright": true, "meaning": "一句解读" },

```

字段约定：

- `gua_lines`、`bian_lines`：六爻**从下往上**排，1 表示阳爻，0 表示阴爻；`moving` 写动爻是第几爻（从下往上数，1–6）。
- 星座：`sign` 填用户自己的星座（由推送方配置）。
- 字数限制：`summary` 不超过 24 字；宜、忌各最多 4 个，每个不超过 6 字；`nabo` 不超过 30 字；每个模块里的白话、解读不超过 60 字。
- 任何模块缺失或为空，Tab5 显示「暂无」，不会报错。外层字段缺失时，对应位置也显示「暂无」。
- 黄历的农历和干支请按实际日期计算后填写，不要编造。

### 4.4 今日学习：`source = "nabo/study/paper | word | point"`

```json
{
  "id": "nabo-2026-10-22-study-paper",
  "ts": "2026-10-22T08:12:00+08:00",
  "source": "nabo/study/paper",
  "priority": "normal",
```

- 每条推送单独成卡，每天建议 1–3 条。

### 4.5 今日待办：`source = "nabo/todo"`

```json
{
  "id": "nabo-2026-10-22-todo-ppt",
  "ts": "2026-10-22T07:45:00+08:00",
  "source": "nabo/todo",
  "priority": "high",
  "title": "09:30 提交病例讨论 PPT 给主任"
}
```

- 一个事项一条推送。
- 有时间的，`title` 以 `HH:MM ` 开头（24 小时制，后面跟一个空格）；没有时间的直接写事项。
- 不要推完成状态，完成与否由 Tab5 本地记录。

## 5. 测试命令（本地模拟）

```bash
export NABO_RELAY="http://<NAS 局域网地址>:8787"
export NABO_TOKEN="<从环境变量或 /data/token.txt 读取，不要贴进聊天>"

# 推一条待办
curl -sS -X POST "$NABO_RELAY/nabo/$NABO_TOKEN/push" \
  -H 'Content-Type: application/json' \
  -d '{"id":"nabo-test-todo-1","ts":"2026-10-22T07:45:00+08:00","source":"nabo/todo","priority":"high","title":"09:30 测试：提交病例讨论 PPT"}'

# 推一条学习
curl -sS -X POST "$NABO_RELAY/nabo/$NABO_TOKEN/push" \
  -H 'Content-Type: application/json' \
  -d '{"id":"nabo-test-word-1","ts":"2026-10-22T08:05:00+08:00","source":"nabo/study/word","priority":"normal","title":"今日 2 个词","body":"sepsis  脓毒症\nlactate  乳酸"}'

# 看收件箱（从头拉；之后用返回的 rev 增量拉）
curl -sS "$NABO_RELAY/nabo/$NABO_TOKEN/inbox?since=0"

# 撤回
curl -sS -X POST "$NABO_RELAY/nabo/$NABO_TOKEN/push" \
  -H 'Content-Type: application/json' -d '{"id":"nabo-test-todo-1","deleted":true}'
```

## 6. 部署注意（改中转站时）

- 改动前先完整备份 `/data`（包括 `relay.js`、`inbox.json`、`podcasts.json`、`music.json`）。
- 不得删除或修改 Muse 已有的节目和收件箱数据；新数据单独存到 `/data/nabo_inbox.json`。
- 模块已写好：`tools/muse-relay/nabo_routes.js`，安装脚本 `tools/muse-relay/enable_nabo.js`，测试 `tools/muse-relay/nabo_routes.test.js`（`node --test` 运行）。
- 部署步骤：
  1. 备份 `/data`。
  2. 把 `nabo_routes.js`、`enable_nabo.js` 放到 `/data`（和 `relay.js` 同一目录）。
  3. 运行 `node /data/enable_nabo.js`。它会先做语法检查，再在 `http.createServer` 入口插入一行，原文件另存为 `relay.js.bak-nabo-<时间>`；已经装过就不会再改。
  4. 只重启 `node /data/relay.js`（由原有 supervisor 拉起），不要动 cloudflared。
  5. 用第 5 节的 curl 验证。
- 中转站已经校验：长度上限；`source`、`priority`、`mood` 只接受上面列出的值；运势的 `body` 必须能解析成 JSON 对象；单个请求不超过 16 KB；最多保留 30 天或 500 条。日志只记 `id`、`source`、`rev` 和字节数，不记正文和 token。
- 经公网隧道访问时同样要求 token。

## 7. 每天的推送节奏（建议）

- 7:00 前：一条 `nabo/fortune`，九个模块尽量填全。
- 白天：看到日程变更就推 `nabo/todo`，一个事项一条，带上时间和合适的 `priority`。
- 学习内容：每天 1–3 条 `nabo/study/*`。
- 推之前先 `GET /inbox` 查一下当天推过什么，同一件事不要推两遍；要改内容就用原来的 `id` 覆盖。
