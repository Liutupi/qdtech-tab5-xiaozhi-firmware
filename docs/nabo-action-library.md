# NABO 动作库：lively-v1

2026-10-12 用户选定 14 条即梦半身动作。实现基于 `firmware-sky` 的
`549f1eb`（持续睡眠动画修复），保留当前工作区的 Muse 修复。

## 播放与编排

- 原待机、工作、入睡、睡眠仍由原状态控制器负责；原帧数、40 ms 时间轴、
  睡眠/唤醒匹配表保留。14 条动作独立保存在 SD 卡上。
- 待机先完整循环原视频，20–45 秒后在中性姿态的循环边界插入一个动作。
  因等待边界，实际间隔可能多出最多 4.52 秒。动作结束后从原待机第零帧继续。
- 同一动作至少间隔 600 秒，不连续重复；表情小动作权重较高，喝水、翻书、
  点赞等权重较低。不是按固定顺序不停播放 14 条。
- 进入倾听可触发 A16，等待回复可触发 A05R1。检测到人声、实际播放音频、
  说话、音乐、手势、应用/相机页面或入睡会立即取消装饰性动作。
  动作不启动音频、不延迟回复、不改变设备状态。
- P01/P02 等所有选定动作都可在空闲时出现。E12R1 只是视觉困倦动作，
  不擅自让设备睡觉；真正入睡仍使用原入睡和持续睡眠流程。

## 构图与资源

所有状态统一使用 B 版宽窗框。人物以同一 .94 比例绕固定位置整体缩放，
不拆手臂、不修改关节运动，不裁掉手来适应窄框。绿幕处理清除与主体分离的
浮点，保留附近发丝。新动作首尾各 6 帧（240 ms）在接近中性姿态处使用
整个人物的预乘透明度混合，第一、末帧与原待机第零帧逐字节一致。

上机后按用户反馈将天空扩为 544×558，512 像素的 B 窗框区左右各增加
16 像素背景余量；横向渐隐从 90 收窄到 16 像素，顶部渐隐为 64 像素。
只向外扩背景，人物与窗框的屏幕坐标不变，不需要重写 SD 资源。
合成器预先计算两套整数采样坐标，并在内部任务栈中分行处理颜色、透明度
和遮挡，避免逐像素重算变换或反复读取 PSRAM；新旧格式、边缘透明度和
更换背景后的结果均通过独立逐像素参考对照及地址/未定义行为检查。

电台实测观察到播放期间 SD worker 的 `pump=0`，摄像头也暂停，未出现分配
失败。按用户播放卡顿反馈，修正电台补充压缩数据时的不必要等待：首帧和
不足 2 KiB 时仍有限等待，已有足够 MP3 数据时非阻塞拉取网络 ring 后立即
解码，避免等待下一批网络包耗尽 I2S 队列。不增加缓冲内存，不改变音频焦点、
重连和歌曲结束语义；原进度日志新增 buffered/ring/interval_ms 便于上机核对。

资源目录：`/sdcard/tab5/nabo/lively-v1/`。有 18 个 `.nab` 文件和
`manifest.json`；原目录下的四个旧 `.nab` 文件保留。缺少新基础片段时回退
到旧路径，某个新动作失败时只禁用该动作。没有新资源时不会请求随机动作。
回退播放仍使用本固件的统一宽框。

新帧包为 NABOSD1 version 3：320×349 RGB565+A8，25 fps，单帧独立 LZ4。
保留原 64 字节头、32 字节索引、CRC；version/format 均为 3，索引 codec=2
表示 LZ4（codec=1 可存原始数据）。CRC 校验编码后的字节。每个 payload
以 128 字节边界对齐，解码长度必须恰好等于 width×height×3，支持随机跳帧，
不用依赖前一帧。version 1/2 的读取策略保持兼容，version 3 必须显式允许场景。

2026 帧总计 191,188,761 字节（约 182.3 MiB）。25 fps 的平均文件读取量
约 2.36 MB/s，最大编码帧 129,836 字节；旧方案为 9.89 MB/s 的原始帧。
这只是数据量，不能据此宣称设备实测 25 fps。

SD 读取、CRC、解码、人物/天空合成仍在优先级 2 的后台任务上。
UI 只交换已完成缓冲，保留两到三个输出缓冲、一个原始帧缓冲及一个编码
缓冲，全部启动时分配；不把全部动作加载到 RAM，不给音频增加队列或等待。
较慢 SD 会跳过过时帧，状态变化会取消旧任务。日志新增 `decode_us`，
仍提供读取、CRC、合成、直接输出和最低可用内存指标。

## 重建与验证

资源制作不写入 SD 卡：

```sh
python3 scripts/prepare_nabo_action_library.py \
  --batch /path/to/2026-10-12-500 \
  --lab /path/to/NABO-sd-animation-lab-20261004 \
  --output /path/to/new-package/tab5/nabo/lively-v1
python3 scripts/validate_nabo_action_library.py \
  /path/to/new-package/tab5/nabo/lively-v1
```

工具要求 numpy、Pillow、scipy、liblz4、ffmpeg 和 C++ 编译器。
macOS 自动寻找 liblz4 失败时添加 `--lz4-library /opt/homebrew/lib/liblz4.dylib`。
工具拒绝覆盖已有资源/预览；验证从实际 RGB565 数据生成设备像素预览，
逐帧对照 liblz4 与固件解码结果、CRC、128 字节对齐、首尾和 B 框范围。

固件使用 ESP-IDF 6.1 和 `scripts/build.py qdtech/tab5 --name qdtech-tab5-native`。
运行 `python3 -m unittest discover -s scripts/tests -v`；设置 `IDF_PATH` 可同时
验证 ESP ROM CRC 适配。自动检查覆盖全部动作、间隔/冷却、抢占、缓冲所有权、
取消、缺卡、超时恢复、损坏数据、LZ4 边界和宽框合成。

安装时需要同时更新应用固件和 SD 新目录。仅更新固件不会得到新动作。
SD 卡须可用至少 200 MiB 空间，先完整复制并验证 manifest 的 SHA-256，
然后再启动新固件。没有修改 OTA 板型、分区、引脚或每日生成的 80 积分预算。

2026-10-12 已将全部资源及同功能主程序装入 P4 rev 1.3 实机，写入哈希通过。
用户确认新动作还算流畅，并在最终修复后确认宽框背景与电台声音正常。
最终 240 秒串口观察中，SD 新动作正常打开，音频播放时 SD worker 停止；
44.1 kHz 电台及 48 kHz 点歌的稳态解码日志间隔连续，未见新的 panic、
断言或看门狗故障。正式 v1.0.11 为同代码的版本号重建，另行校验镜像。

仍需扩展验收：持续睡眠及唤醒、对话/打断、完整播客、应用返回、长时间稳定性，
以及 SD/Wi-Fi 竞争下的最低内存和慢读恢复。25 fps 是资源时间轴，
实际显示受 SD 速度及合成影响，不宣称设备恒定 25 fps。
