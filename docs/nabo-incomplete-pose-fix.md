# NABO OK/鼓励手势只剩四肢：解码修复

原素材及上身图层包含完整身体。Wink/Encourage共用头和上身大图层，
解码像素分别505,596和503,744字节；手/脚为独立小PNG。受限内存下
LodePNG临时分配失败，上身未画出，小图层仍能显示。

使用相同LVGL及真实编译PNG，在1400KiB的LVGL内存池、1MiB图片缓存下
复现：腿成功、Wink上身PNG失败（lv_realloc/Error decoding PNG）、手和
袖口成功。该宿主测试说明故障机制，不能替代每台实机的内存测量。

两个上身现在编码为LZ4压缩的RGB565A8。沿用已有RGB565屏幕颜色精度，
透明度逐字节保存，无新绘画、调色、裁切、比例或锚点变化。解压像素
分别379,197和377,808字节，避免PNG扫描线/滤波的额外临时峰值。
压缩体分别142,138和140,146字节（含12字节LVGL压缩头），较原PNG
合计只多64,326字节，而不是把两张完整raw图直接塞进应用。

原生构建入口启用内部LZ4和RAM binary decoder。脚本使用项目内的
纯Python块编码器，不要求另装Python压缩库；与LVGL自带C解码器验证
了边界、重复、随机、实际图层块及字节一致性。

同一受限内存宿主检查中，改成LZ4后腿/上身/手/袖口全部成功。
进入动作前还会检查并暂时pin住整套必要图层。任一加载失败就保留
完整基础形象并记NaboPose告警，避免先隐藏身体再显示已加载的四肢。
检查结构只在动作开始时分配，动画每帧沿用既有骨架和小区域更新。

所有其它51张图片数组字节不变。配置、唤醒词、模型资源、IR等用户
其它工作均保留。SD迁移仍为另一待整合项；不要用之前16帧SD原型覆盖
最新骨架素材。此修复先处理当前已发现的解码缺失。
